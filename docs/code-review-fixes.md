# 源码审查修复（2026-10-13）

本次修改修复数据完整性和操作一致性，未应用暂存的自定义提醒补丁，也未发布新版本。

- 存档不存在、存档无法读取、存档解析失败分开处理。失败时保留原始数据并暂停自动保存，页面允许下载原始存档和当前工作数据。恢复保存或导入有效备份前，会先将原存档另存到独立的 recovery 键；备份失败则不覆盖原存档。
- 保存失败会显示持续提示，可导出或重试。一次复合操作只保存最终状态。
- 编辑任务、更换项目、调整上级共用子树放置规则，子孙的项目归属一起变更，拒绝循环与无效落点。
- 历史在一次操作结束时计算最终增量；连续编辑、批量删除依赖、重复文件夹改名及新增后删除均可正确撤回或抵消。不存在的可选字段也能原样恢复。
- 保存与界面导出使用同一个完整数据快照，待办文件夹名称随导出保留。
- 文件导入和 store 导入共同验证任务 ID、项目归属、父节点、循环和基础字段，拒绝超过 256 层的任务树，旧数据的可选字段仍会补全。
- 历史状态使用对应日期的暂停区间；严格进度也在计算入口截断未来日志。
- 父任务日期在工作数据操作中同步，日志变化也会触发同步，不再依赖 App 的 effect；加载和导入后同样有效。
- 更新与提醒独立为 store 模块，任务树、日志和当日汇总共享弱引用索引。跨午夜重新计算当日状态和提醒内容。
- 写日志的表单明确说明当天写入、午夜锁定、无法补写的规则，三种语言保持完整。

验证入口为 `npm test`。新增 `check-data-integrity.mjs` 直接执行真实 store 的编辑、导出和恢复动作，并覆盖损坏存档、读写失败、复合撤销、错误导入、历史暂停和原子日期同步。页面存档提示另有 React 静态渲染检查。

自动化检查不替代真实 Windows 通知发送和浏览器点击验证；这两项需要可用的桌面或浏览器会话。
