# 通知文案与判断

这份文件是**填空用的**。你改，我接进代码。

- **第一、二节是结构** —— 改了我会动 `src/lib/reminder.ts` 里那张 `SLOTS` 表（时段、边界、选材全在一张表里，改一格只动一行）
- **第三到七节是文案** —— 改了只是字符串，逻辑不动。这些**在软件的设置里也能改**，你在这里填的是**出厂默认值**

怎么改：直接在下面写就行。填空、删掉或补上 ✓、改时间、加删行，都可以。改完跟我说一声。

**你现在看到的是我提的方案，不是既成事实。** 尤其第一、二节基本全是我的猜测，请当成草稿改。

## 一、时段：只管问候语

八个时段覆盖一整天，**边界首尾相接**，没有空档也没有重叠。

| # | 时段 | 起 | 止 | 这句话的语气 |
|---|------|-------|-------|------------------|
| 1 | 凌晨 | 00:00 | 06:00 | 没睡，或者刚醒 |
| 2 | 早上 | 06:00 | 08:00 | 起床、通勤 |
| 3 | 上午 | 08:00 | 12:00 | 开始干活 |
| 4 | 中午 | 12:00 | 13:30 | 午休，半天过去了 |
| 5 | 下午 | 13:30 | 18:00 | 还在干活 |
| 6 | 傍晚 | 18:00 | 19:00 | 收工，结算 |
| 7 | 晚上 | 19:00 | 22:00 | 在家 |
| 8 | 深夜 | 22:00 | 24:00 | 睡前，说句收场的话 |

**时段只决定两件事：问候语，和这句话听起来是什么调子。** 它**不决定报什么** —— 这一条是这一版改掉的核心，见下面。

> **时段永远不决定"发不发"，也不决定"发什么"。** 你把一条规则设到 03:00，它照发、照用自己那套内容，只是开口说"还没睡"。

## 二、三条固定发送，两种内容

一天三条，**内容由这条规则自己决定，不由它落在哪个钟点决定**。

| 规则 | 时间 | 内容 |
|------|------|------|
| 早上 | 07:00 | **日报「今天」那四个数** |
| 中午 | 12:30 | **一句话**：没写日志就催日志，写了就报还剩多少 |
| 傍晚 | 18:30 | 同中午 |

**这一版改的就是这件事。** 之前内容是挂在时段上的，于是"早上那条"落在深夜就变成了另一种消息 —— 你看到的那三条带任务名的通知就是这么来的：它按 22:xx 那个时段的格式发的。现在**一条规则从头到尾只有一种内容**，落在哪个钟点只换问候语。

### 早上 —— 完完全全按日报里的发

就是日报「今天」那四行，**一个任务名都不出现**：

```
早上好

任务清单 · 5
到期与逾期 · 7
临时事务 · 3
日常安排 · 2
```

- **任务清单** = 今天有日志义务的任务数
- **到期与逾期** = 已逾期 + 今天到期 + 快到期（跟日报一样折成一个数）
- **临时事务**、**日常安排** 各一个数
- **「今天该开始」不在里面** —— 日报不问这个问题

那天真的什么都没有，这条也照发，说的是日报那句「今天没有欠账。」—— 早上是你检查"提醒到底通不通"的时刻，不发跟坏掉长得一模一样。

### 中午／傍晚 —— 一句话

| 当天日志 | 这条说什么 |
|---|---|
| **一篇都没写** | 只提醒去写日志（文案见 §七） |
| **写了（哪怕只一篇）** | 报一个总数 + 三条明细（文案见 §七） |
| 两样都没有 | **不发** |

写了之后的样子：

```
还有 10 项事项待处理，其中：
- 5 项任务
- 3 项临时事务
- 2 项日常安排
```

三个数就是日报「今天」的后三行（**任务** = 日报那个「到期与逾期」），**日志不在里面** —— 这是"日志已经写了"的分支，上面那条已经说过了。空的分组不画，不写成 `- 0 项日常安排`。

> **「日志未更新」= 今天一篇都没写**，不是"还没全写完"。一开始我按后者做的，结果是：写了两篇日志它还在催 —— 因为看板上跑着的严格任务有五个，它们**每天都欠一篇**，只要没全写完这个提醒就永远亮着，跟坏掉没区别。

### 几条共同的

> **每条都带一个「我知道了」按钮。** 用 Windows 的 *reminder* 场景 + 一个按钮：横幅不会五秒后自己滑走，而是留在屏幕上直到被处理 —— 要么点「我知道了」，要么点右上角那个 ×。按钮上的字跟着界面语言走。

> **没开机就补发，但只补一条。** 电脑关着跨过了几个发送点，开机后那几条**一起**到期 —— 只发其中最后一条，用**当时**的语气（20:00 开机不会跟你说"早上好"），前面几条记作错过。三条一摸一样的通知就是这么修掉的。

## 三、什么时候真的发

### 到点就发，每条一次

一天三条，各自在自己的时刻发一次，互不影响。**一条发过了就不再发** —— 发送端每 15 分钟被计划任务叫醒一次，一天被叫 96 次，95 次都停在这一句上。

### 没开机：只补最后一条

电脑关着跨过了几个发送点，开机后那几条**一起**到期。只发其中**最后**一条，用**当时**的问候语，前面几条记作错过。

> 三条一摸一样的通知就是这么来的 —— 它们同时到期，又同时落在同一个钟点，于是说了三遍同一句话。错过的那几条不是"攒着"，是"那个时刻已经过去了"。

### 通知会一直挂着

不是弹几秒就走。用 Windows 的 *reminder* 场景 + 一个「我知道了」按钮，横幅**留在屏幕上直到被处理** —— 要么点按钮，要么点右上角那个 ×。

> 机制实测过：挂得住不自动消失、按钮能点、点击能传回进程。

**但点击目前没有记录。** 这一版只做了"挂住 + 有按钮"，没有把"点了"写回任何地方 —— 因为现在没有任何东西依赖它。见下。

### 「已读抑制」还没做

早先聊过一套规则：上一条没确认就不发下一条；一个时段报过的内容下一个时段不重复。**没实现。**

原因是它依赖"已读"，而"已读"唯一的用处是那个日志升级规则（"早上提过日志、你也确认了，中午就不列条目改成催一句"）—— 那条已经被更简单的规则取代了（§二：**今天一篇都没写**就催，写了就报数）。没有第二个消费者，读状态就只是一份没人看的记录。

要做的话说一声：`sent.json` 里加一个确认字段、Rust 那边 `wait_for_action` 守着就行，机制是通的。

### 不做：随机小互动

久坐提醒那类，**取消了**。通知只有那三条，都从看板来。

## 七、消息正文

**没有"条目格式"这一节了。** 原来有两条格式（`· 任务名 —— 截止 日期` / `· 任务名`），是给"列出任务名"那种消息用的 —— 那种消息已经没有了（§二），键也一并删了。

### 早上那四行

每行是 `标签 · 数字`。标签来自 §六 的栏目名和两个组名（任务清单 / 到期与逾期），数字是当天的计数。

### 中午／傍晚那三句

这三句是**整条消息的全部**（§二）。问候语照旧在前面，收尾句照旧可有可无。

| 什么时候 | 文案 | 现在 |
|---|---|---|
| 一篇日志都没写 | | 今天的日志还没写 —— 记一笔，顺手把任务进度同步了。 |
| 写了，第一行 | | 还有 {count} 项事项待处理，其中： |
| 写了，下面每一行 | | - {count} 项{label} |

> 这三条也能在设置里改，跟其它文案一样。第一行的 `{count}` 是**总数**（等于下面几行加起来），`{label}` 是那一行的组名（任务／临时事务／日常安排）。

## 八、应用内日报

日报是侧栏顶部（软件名那一排右端）那个报纸图标的按钮点开的面板。当天没点开过，按钮右上角挂一个红点，点开就消，隔天重现。

**它是一份回顾，不是一份清单。** 只报数字，不报名字 —— 名字是「今天」页的事，数字才是"要不要去看一眼"的依据。

### 昨日 —— 结果

| 行 | 数的是什么 |
|---|---|
| 日志 | 昨天写下的**日志条数** / 昨天欠的日志数（不是任务数：一个任务写两条就是两篇） |
| 完成率 | 昨天有日志义务、且真的写了日志的任务占比 |

> 和日历格子、和「今天」页那个进度环取自同一个函数（`strictLogRate`），所以这里写 60%，那两处也一定是 60%。

### 今天 —— 规模

| 行 | 内容 |
|---|---|
| 任务清单 | **今天有日志义务的最小任务数**（`strictLogRate(今天).total`） |
| 到期与逾期 | 后面三项的**合计**，点开才展开 |
| ↳ 今天到期 | 缩进 |
| ↳ 已逾期 | 缩进 |
| ↳ 快到期 | 缩进 |
| 临时事务 | |
| 日常安排 | |

> 三个日期项合成一行 —— 「今天到期 4 / 已逾期 1 / 快到期 2」是三行同一种消息，把读者的视线挡了三次。它们本来就是一个念头（**有什么到期了、迟了多久**），所以给一个合计，想看细节再点开。
>
> **0 也要画。** 「已逾期 0」是好消息，而且是这个功能存在的意义所在。只有全空的时候才换成下面那句话 —— 一列 0 排下来，不如一句话。

### 格式

三档：

1. **小节** —— 昨日／今天各一条横线。「昨日」整体压暗（标题灰、数字正常），因为已经过去了，这份面板要说的是今天
2. **行** —— 灰标签 + 等宽亮色数字右对齐（所以数字能对齐成一列）。标签前一个圆点
3. **子行** —— 缩进一档、字号小一号。不展开的行给圆点，能展开的给箭头（箭头转动表示展开）

> **0 会变暗。** 有数的行亮着，是 0 的行退到背景里 —— 这样一眼扫过去，先看到的就是今天真正有东西的那几行。
>
> **完成率除了数字还有一根横条**，颜色用的是「今天」页那个进度环同一对（满 100% 换一个色）—— 同一个概念用同一套颜色。

### 它和通知是一套词

「今天」那四行的标签**就是通知早上那四行用的同一组键**（任务清单 / 到期与逾期 / 临时事务 / 日常安排），在设置里改一处两处都变。昨日那三行和格式是界面文字，不跟着走。

| | 文案 |
|---|---|
| 面板标题 | 日报 |
| 今天完全没事时说什么 | 今天没有欠账。 |

> **它和「今天」页的关系要说清楚**：内容跟「今天」页是同一份数据。日报的价值是**一个每天要消的红点 + 一屏看全**；「今天」页是随时可去的常驻页。
