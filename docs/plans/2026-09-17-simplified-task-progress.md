# 简化任务：把「非严格」从日历说了算改成你说了算

## 背景

非严格任务现在的进度**完全由日历推**（`autoProgress` = 已过天数 ÷ 总天数，[progress.ts:6](src/lib/progress.ts#L6)）：你什么都不做它也会涨，窗口走完就自动算完成，热力图还把过去每一天都记成「完成」。用户的判断是「这种设计只会让人自欺欺人」，一度想删掉这一类。

但删掉它意味着每个阶段叶子任务都欠日志——三条并行任务就是每天三篇。所以这一轮**保留但重做**：简化任务仍然存在，但不再由日历推着走，改成每天由你点一下确认，点过的日子才算数。它不再骗人，只是比写日志省事。

同时把默认值反过来：新建任务**默认走日志**，那个选框改成「取消日志限制」并挪到表单最后，勾选时弹窗把代价讲清楚。设计意图就是**优先推荐日志依赖任务，不推荐简化任务**。

## 屏幕上会变成什么样

- 新建任务表单**最后**一项是「取消日志限制」，默认不勾 → 默认有日志义务。勾它先弹确认框。
- 简化任务的行上，原来日志按钮那个位置（[DayBoard.tsx:368-382](src/components/DayBoard.tsx#L368-L382)）换成一个**确认勾选框**，外观照搬临时事务那个 14×14 的方框（[DayBoard.tsx:465-474](src/components/DayBoard.tsx#L465-L474)）：点一下表示「今天我做了」。
- **今天和过去的每一天都能点，未来的不能点**（所以漏掉的那天可以到日历里点开那天补上）。同一个组件同时服务今日页和日期详情面板，两边自动都有。
- 进度 = **已确认天数 ÷ 可确认天数**，可确认天数 = 窗口里**没被暂停**的那些天。
- 过了结束日期还没确认满 → **显示逾期**（推翻「非严格任务没有逾期态」——那条建立在「它到期会自动完成」上，而它不会再自动完成了）。
- 热力图上，简化任务只有**点过确认的那天**才算完成。

## 确认弹窗的文案（用户定稿，逐字照用）

标题：**确定不要日志监督吗？**

带强调记号的原文（**这就是要存进字典的字符串，原文照录**）：

```
脱离日志系统则该任务将*不会拥有历史日志*，且不会在 log 页面里被统一管理。

本任务将采用一种*极度简化*的进度计算方式，即每日只需要*手动点击按钮*来确认完成，然后系统自动按已过日期 ÷ 总日期进行进度累计，否则不予累计进度。如果你有某日忘了点按钮，则会在以后的日报里对你进行提醒，你可以按实际需求暂时忽略／将确认补上，也就是再点一下按钮的事。

这也就意味着，本任务可能将*/无法精确反应任务实际进度*/，且确认某日本任务完成的*/监督力度几乎为 0 */。**//请你确保有足够的自律能力脱离日志系统监督**//。
```

按钮：`[返回]`（左） `[仍要取消]`（右）

### 强调记号的规则（用户给）

- `*…*` = **加粗**。重复写（`**`）与写一个等价 —— 加粗没有档位。
- `/…/` = **放大**，**斜杠个数即档位**：1 → `1.08em`、2 → `1.14em`、3 及以上 → `1.20em`（用户给了 120% 的上限，三档是我从他给的上限倒推的，梯度要改说一声）。
- 两者同时用（`*/…*/`、`**//…**//`）= 加粗 + 对应档位放大。
- 用 `em` 而不是 px，所以上限在任何主题/字号下都成立。
- **半角 `/` 才是记号**；正文里那个全角 `／`（`忽略／将确认补上`）不是，要留断言盯着，别让它在英文/法文版里被误伤。
- 落单的记号（只有开没有合）**按字面输出**，不许吞掉后面的文字。

（用户改过两处：分母改成「已过 ÷ 总」；标题定为他选的「确定不要日志监督吗？」。三语照这份定稿翻。

**第二段末句提到的「日报提醒」本轮不做，文案按用户要求原样保留** —— 弹窗会先承诺一件还不存在的事，这是他自己决定的，不是漏项。做那条提醒时的候选落点（他没有选，留待那时再定）：今日页任务行上挂一个「有 N 天没点」的角标，和严格任务那个 amber 的 `No log` 角标同款。）

## 实现清单

### 库层

**1. `src/types.ts`** — `Task` 加一个字段：

```ts
confirmedDays: string[] // yyyy-MM-dd，简化任务已确认的天
```

存日期数组而不是带数字的记录：简化任务的全部意义就是「点过没有、增加了多少不归你填」。**不复用 `TaskLog`** —— 用户明确要求它不产生历史日志、不被日志页统计（存成空内容日志会漏进 `logCount`、日日志弹窗和日志页）。

**2. `src/lib/progress.ts`** — 换掉非严格那条分支（`:26`）：

- 分子 = `confirmedDays` 里落在 `[startDate, endDate]` 内**且 `≤ onDate`** 的天数。裁到 `onDate` 是关键：`dayTasks.ts` 的 `progressBefore`（`:163`）正是靠传入「前一天」来问「那天开工时完成了没有」，不裁就会把今天点的那格算进昨天。
- 分母 = `[startDate, endDate]` 里**没被暂停**的天数，`Math.max(1, …)` 兜底（和现有 `totalDays` 写法一致，退化输入不炸）。
- 顺带删两处死代码：`autoProgress`（全仓库只此一处调用）和 `effectiveDate` 的暂停冻结（`:25`）。冻结不但没用了，还会**遮掉恢复之后点的确认**，必须去掉。
- 严格任务那条老的「已写天数 ÷ 总天数」兜底：分母一起改成「窗口减暂停日」。它只被旧数据走到。

**3. `isPausedOnDay` 搬进 `progress.ts`**（定义现在在 [dayTasks.ts:82](src/lib/dayTasks.ts#L82)）。新分母需要它，而依赖方向只能这么走：`dayTasks` 已经 import 了 `progress`，反向导入会形成 `progress → dayTasks → tree → progress` 的环。`progress.ts` 现在只依赖 `types` 和 `dates`，是叶子，加得进去。判定逻辑一个字不改，`dayTasks.ts` 与 `heatmap.ts:3` 改成从 `./progress` 拿。

**4. `src/lib/tree.ts`** — `:85` 的 `task.strictProgress &&` 去掉，让简化任务也能逾期。`:83` 的「进度 ≥100 → completed」在它前面，确认满的仍然先判完成。

**5. `src/lib/heatmap.ts`** — `:70` 的 `: day < today` 换成「那天在 `confirmedDays` 里」（顺手做成 Set 查表，和上面的 `logged` 一致）。这条同时修掉 FEATURES 里记着的「非严格任务多的板子热力图退化成一块纯色」。

**6. `src/lib/dayTasks.ts`**
- 新增 `isNonStrictLeaf`（`!isTodo && phase && !strictProgress && 无子任务`），照 `isStrictLeaf`（`:95`）写。
- `DayRow` 加 `plain: boolean`（非严格叶子）和 `confirmedOnDay: boolean`。
- `:374` 的 `overdue` 判定现在只认严格任务，要一并纳入简化叶子，否则逾期任务在日面板里不出现。

**7. 存储** — `useStore.ts` 的 `addTask` 字面量（`:334-353`）加 `confirmedDays: []`；新增 action `toggleTaskDay(taskId, day)`，照 `toggleChore`（`:553-563`）的 guard → map → 更新 `updatedAt` 写法；`storage.ts` 的 `normalize` 照 `:194` `pauses` 那行加回填（**不给待办强制清空** —— 日志对待办也是留着的，转回来还在）。

## 不做

- 不改严格任务的日志机制（上一次刚改完）。
- 不给简化任务加「取消确认」之外的历史编辑：勾选框能取消勾选（和日志能删一样），但**没有任何地方能填数字**。
- 不动甘特图上非严格任务的进度条画法（数值变了，画法不变）。
- **漏点的「日报提醒」不做**（用户明确：后续再补，文案先留着）。
- 不改日面板/今日页之外的地方加确认入口 —— 日历格子只列里程碑任务，本来就没有逐任务控件，点格子开日面板已经够了。
