# 今天页：日程表 + 每日任务规划

> 2026-10-27 获批，2026-10-28 随 v0.18.0 实现。正文已按最终实现改写；与获批稿不同的地方就地标 `〔改动 N〕`，文末是汇总。同一个计划文件第二天又被《启动规划弹窗》覆盖，本份是从对话记录还原的 —— 见 `PLANS.md` 的阅读须知。

## Context

今天的今日页会把「当天在期」的每个任务都列出来：日环、日历义务方块、热力图和日报也按同一份名单算欠账。任务一多，每天看到的是一整墙做不完的活，没做完就被记成「没做」。用户真正想管的是「今天能做完哪些」和「几点做、几点前交」。

今天页因此改成三个页签：今日 / 明日 / 本周。今日与明日是「任务 + 日常安排/临时事务 + 一条单日 24 小时时间轴」；本周是 7 列 × 24 小时的课程表。日程表里放任务时段、自由事件和精确到时刻的截止点，每天带一个负载读数。

同时加入每日规划：每天从当天在期的任务里挑真正要做的。做过计划的日子，清单、日环、日历义务、热力图和日报只算计划内的任务；没做计划的日子维持旧规则。

**任何时候都不会自动写「当天未排期」之类的日志条目。** 计划外的严格任务当天不算欠日志，不进任何统计；用户仍然可以手动写。任务的进度分母不变。

## 最终实现的形状

### 今天页骨架

```
[ 今日 | 明日 | 本周 ]

今日/明日：
┌──────────────────────────────┬──────────────────┐
│ 任务清单 │ 日常安排 / 临时事务 │ 单日 24h 时间轴   │
└──────────────────────────────┴──────────────────┘

本周：
┌────────────────────────────────────────────┐
│ 周一 … 周日（7 列 × 24h）                   │
└────────────────────────────────────────────┘
```

- 今日 / 明日：左卡片 `DayBoard layout="side"`（任务在左，日常安排与临时事务仍在新的一列），右卡片单日 `Timetable`，宽 `clamp(320px,32%,440px)`。两块各自滚动。〔改动 1、2〕
- 本周：`Timetable days={7}` 包在一张圆角卡片里。〔改动 9〕
- 旧的今日/明日并排 + 聚焦变宽布局移除；`DayBoard` 的 `side` 布局因此成为主布局。
- 今日页签可勾日常安排；明日页签只能看/加临时事务。

### 日程表（`Timetable.tsx`）

- 一个组件同时服务单日与本周。纵轴 0–24 点，左边 46px 时间槽，表头与时间槽 sticky。
- 单日每小时 44px、挂载滚到 7:00、有半小时线；本周每小时 32px、从 0 点开始、无半小时线。〔改动 3〕
- 三种块：任务时段（关联任务时用项目色左边框 + 淡底）、自由事件（`panel2` + 边框）、截止点（零时长，一条带小旗的线，不参与分道）。重叠块用 `packBlocks` 贪心分道。
- 点空白格按半小时吸附创建；点块编辑/删除；不做拖拽。
- 今天列画当前时刻线（`in-progress` 信号色，60 秒刷新）。
- 每天列头：日期 + 负载读数（`LoadMeter`）。
- 负载 = 已排小时 ÷ 可用小时，默认 8，列头可直接改（0–24，0.5 步进）。颜色三档：强调色（舒适）/ 琥珀（≥80%）/ 红（超容量）；超出的一段画斜纹，容量处画竖线，文字写「还剩 / 超载 X 小时」。只算有时长的块，截止点不计时。〔改动 4〕

### 规划（`PlanDialog.tsx`）

- 任务区标题右侧的「规划 / 调整」打开选择框。
- 候选 = 不带计划的 `daySummary`（在期 + 逾期、叶子、去掉待办/归档），排除已完成（除非已在计划里）；再并上计划里仍有、但已不在候选里的 id（标「当天未排期」）。
- 未规划时默认全选；保存 → `setDayPlan(date, ids, hours)`；「休息日」→ `setDayPlan(date, [])`；「恢复自动」→ `setDayPlan(date, null)`。
- 每个勾上的任务填当天小时（0–24，0.5 步进，空 = 0）；「默认」把当前值写进 `Prefs.taskDefaultHours`，下次预填。〔改动 5〕
- 顶部负载用草稿实时计算，不是保存后的计划。
- 计划与日程块**不进撤销历史**。删除任务/项目不清理计划里的 id —— 撤销把任务带回来时，它在计划里的位置还在。

### 计划感知的日规则

`DayPlan.taskIds` 三种状态：缺省 = 未规划；`[]` = 休息日；有值 = 只算这些。父任务 id 在读取时展开到全部后代（`plannedIdSet`）。

| 位置 | 行为 |
|---|---|
| `daySummary` / `strictLogRate` | 有计划只留计划内的任务；空计划得到空清单、环 0/0 |
| `CalendarPage` 的义务方块 / `worked` | 按当天计划过滤；空计划当天不标 |
| `DailyReport` 昨天 recap | `strictLogRate` 与 `written` 一起按昨天计划过滤，避免 3/2 |
| `CompletionHeatmap` | 每个 day 先取计划内 id；空计划 total = 0 |
| `TaskDetailPanel` | `pendingLogsUnder` 传今天计划；`plannedStrictLeafUnder` 决定要不要显示「全部已填」 |
| `lib/reminder.ts` / `reminderSlice` | `Board.dayPlans` 必填；计划改了重写提醒文件 |

不改：`effectiveStates` / `taskProgress` / `deriveTaskStatus`（进度仍按排期天数）、`dayStates` / `milestonesOnDay`、`summary.logCount`、Manage / Gantt / Logs / 侧栏。

### 数据

```ts
DayPlan { date; taskIds?: string[]; capacityHours?: number; hours?: Record<string, number> }
ScheduleBlock { id; date; start; end; title; taskId?; deadline? }
```

- `hours` 是加载荷之后加的（见修订 5）；key ∈ `taskIds`。
- 持久化注册点：`types.ts`、`storage.ts`（`PersistedData` / `workData` / `normalize` / `exportJson` / `prepareData`）、`seed.ts`、`useStore.ts`（State / 初始态 / 保存订阅）、`reminderSlice.ts`。
- 读入清洗：坏行丢弃；日期重复后一条胜出；坏 `taskIds` 读成「未规划」而不是休息日；容量 0–24；`hours` 只在有合法 `taskIds` 时保留。
- `validateData` 刻意不拒绝这两个集合：一条坏行不该让整个看板打不开。

## 获批之后的修订

1. **布局改成了三列。** 获批稿是 `DayBoard`（stack）+ 单日时间轴两列；实现时按用户要求把日常安排与临时事务放回「任务清单右侧」的独立一列，时间轴再往右，宽度从 `clamp(280px,30%,360px)` 放大到 `clamp(320px,32%,440px)`。用户原话：「你要把日常安排和临时事项像原来一样放在新的一列 任务清单右侧」。
2. **视觉语言不在原计划里。** 加上圆角卡片、标题区的径向渐变 + 点阵、pill 分段控件、soft 输入与 Stat。中间曾在卡片底部加过一枚很淡的「周几」水印，用户说「最底下那个暗淡的周二太抽象了」，删除。
3. **时间轴的比例。** 获批稿写单日 32px、本周 28px；实现时单日 28px 滚不到 7:00（被夹到约 2 小时），改成单日 44 / 本周 32，单日滚到 7:00、本周从 0 开始，并只给单日加半小时线。
4. **负载从一行数字变成一块仪表。** 用户先后要求「负载的ui优化一下 现在不是很直观明显」「进度条希望有颜色变化 红黄蓝」「负载进度条的框（不是进度条）的颜色和背景很相近，区分开来」。最终 `LoadMeter` 有标签、可编辑容量、三档颜色、容量线、超载斜纹，轨道用 `bg-bg/50` + 边框 + 内阴影和表头分开。
5. **任务本身开始计时，负载变成两层的合成。** 这是获批后被推翻的最大一处：原方案的负载只看日程块，用户指出勾任务时数字不动，且意识到「任务和负载之间的关系」要定。最终 `DayPlan` 加 `hours`，任务右侧可填当天小时、可勾选存为默认工时（`Prefs.taskDefaultHours`），`dayLoad` 改成「计划内任务取块时长与填写小时的较大者，自由事件与未计划任务块照常计入」；日程表列头与规划框共用这个函数。
6. **时间轴加了鼠标悬停高亮。** 获批稿没有；用户追加：半小时横带 + 小时数字变亮 + 列头描边。
7. **演示数据更新。** 获批稿没有；用户要求「更新演示数据用于功能测试」。`scripts/demo-seed.mjs` 增加 4 份计划、11 个日程块，并断言今天接近满、明天超载、后天舒适、休息日存活。
8. **启动规划弹窗不是这份计划。** `PlanDialog` 后来被复用为启动弹窗（`prompt` 模式），见 `2026-10-28-day-plan-prompt.md`；右侧标签、意见箱、重要更新弹窗同样都是之后的追加需求。
9. **周视图是卡片，不是铺满到边。** 获批稿写「铺满整页」；最终外层是一张 `rounded-2xl` 卡片，四周留 12px。
10. **验证工具补了 `check-schedule.mjs`。** 获批稿列了要验证的规则；最终新增该脚本，并改了 `check-day-obligations` / `check-heatmap` / `check-reminder` / `check-data-integrity` 的用例，总数到 21 项。
