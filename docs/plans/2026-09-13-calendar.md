# Calendar 改造：开始/截止里程碑 + 日志纪律水位图

## Context

Calendar 现在同时想干三件事，每件都只干了一半：

1. **当日程视图**——但格子里的 chip 只认 `startDate`（[CalendarPage.tsx:22-31](src/pages/CalendarPage.tsx#L22-L31)），一个跨三周的任务只在开始那天出现一次，表达不出时长、重叠和负载。而这些是甘特图的主场，且做得对。
2. **当某天的工作台**——但这其实是点击之后 DayDetailPanel 的功劳，网格本身没参与。
3. **当日志纪律图**——每格的 `done/total` 覆盖率。**这是日历唯一不可替代的东西。**

改造方向：把第 1 件事做对（格子改为「今天开始 / 今天截止」的里程碑），把第 2 件让给面板，把第 3 件做成整月可读的水位图。

**已定决策**：格子列「开始/截止」两类；Calendar 不跟随项目筛选，保持全局总览；演示数据只改 `seed-tutorial` 分支，不进 main。

---

## 一、格子内容：开始 / 截止

现在每格画的是「startDate 等于今天」的任务（[CalendarPage.tsx:111-124](src/pages/CalendarPage.tsx#L111-L124)）。改为两组：

- **▶ 今天开始**——`startDate === day` 的叶子任务
- **⏹ 今天截止**——`endDate === day` 的叶子任务

```
┌────────────────┐
│ 12        3/5 │   ← 日期 + 覆盖率数字（保留）
│ ⏹ 电机测试      │   ← 截止优先排在前
│ ▶ 设计稿        │
│ ▶ PCB 布线      │
└────────────────┘
    ↑ 格子底部的水位填充在内容之下
```

规则：

- **只列叶子任务**（`!tasks.some(x => x.parentId === t.id)`）。父任务的起止是从子任务推导的（`effectiveStates` 取子任务的最早开始/最晚结束），列出父任务会和它的子任务在同一格重复。这条与全站其它地方一致（Manage 的计数、覆盖率环都只算叶子）。
- 长期目标（`type === 'long-term'`）可以出现在 `starts`（它有真实开始日），但绝不会出现在 `due`（`endDate` 恒为 null，天然排除）。
- 待办（`isTodo`）无日期，两组都不进。
- **同一天既开始又截止的任务只进 `due`**，不占两行——一天期的任务里"截止"是更紧急的事实。
- 排序：`due` 在前、`starts` 在后；组内按状态紧迫度（复用 `dayTasks.ts` 已有的 `STATUS_RANK`，[dayTasks.ts:39-46](src/lib/dayTasks.ts#L39-L46)），再按名称。
- 超出部分保留现在的 `+N more` 折叠。

"今天该做的全部活"不在这里列——那是点开格子后 DayDetailPanel 的完整版。

图标用 lucide（已是依赖）：`Play` 表示开始、`Flag` 表示截止。chip 的状态底色维持现状，所以每个 chip 同时携带"种类"和"状态"两个信息。

## 二、水位填充与格子状态

格子里的 `done/total` 小字升级为**从底部往上灌的半透明水位**，高度 = 当天严格日志完成率。42 格连起来是一张水情图。

**水位必须是实心的**——顶部那条边界要清晰，否则高度的比值读不准。"不发硬"靠**颜色取低透明度**解决，不是靠渐隐顶部：

```css
/* 水位块，绝对定位贴在格子底部，内容之下 */
position: absolute; inset-inline: 0; bottom: 0;
height: <pct>%;
background: rgba(C, 0.35);          /* 实心，弱透明度 */
```

五种格子状态：

| 状态 | 判定 | 水体 | 边框 | 辉光 |
|---|---|---|---|---|
| **未来日** | `day > today` | 不画 | 不加 | 无 |
| **清白日** | 已过去/今天，`total === 0` | 不画 | 绿 inset ring `rgba(63,185,80,0.30)` | 无 |
| **欠账日** | `done === 0` | 4px 贴底，`rgba(248,81,73,0.45)` | 常规 | 无 |
| **部分** | `1–89%` | `pct%`，`rgba(227,179,65,0.35)` | 常规 | 无 |
| **接近完成** | `≥ 90%` | `pct%`（100% 时换 `rgba(63,185,80,0.32)`） | 常规 | 轻微，`0 0 8px rgba(C,0.20)`，C 同水体色 |

两点实现约束：

- **边框只能用 inset ring，不能用 border。** 格子现在只有 `border-r border-b border-line`（[CalendarPage.tsx:95](src/pages/CalendarPage.tsx#L95)），改 border 颜色只会染两条边。用 `box-shadow: inset 0 0 0 1px <color>` 才能出完整一圈，且不挤动布局。
- **辉光的颜色跟随水体**：95% 那天是琥珀辉光，100% 那天是绿辉光。辉光强度必须**明确弱于选中态的 `ring-accent`**（那是满不透明度的 1px ring）。

**无障碍**：`done/total` 数字**必须保留**在右上角。这不是冗余——[ProgressRing.tsx:17-23](src/components/ProgressRing.tsx#L17-L23) 的注释已写明"绿和琥珀在红绿色盲下只差 ΔE 3.8，颜色绝不能是唯一通道"。另加 `title` 与 `aria-label` 描述完整状态。

**今日/选中态**：现有的 `bg-accent/5`（今天）和 `bg-accent/10 ring-1 ring-accent`（选中）保持不变，叠在水位之上。accent 蓝专属于"今天/选中"。

### 关于 ≥90% 阈值的算术

按目前的种子数据，**每天严格任务数都在 5 个以内，所以 `≥90%` 实际只有 `100%` 能命中**（2/2、3/3、5/5 都是 100%；4/5 只有 80%）。要出现 90–99% 的日子，那天至少得有 10 个严格任务。

建议**保留阈值不动**——它在任务多的用户那里才有意义，在本数据集里退化成"灌满才发光"，而这个语义反而更利落。不为了演示一个中间档去人为堆 10 个任务。

## 三、未来日的修正（Calendar 与 DayDetailPanel 同源 bug）

`strictLogRate`（[dayTasks.ts:144-164](src/lib/dayTasks.ts#L144-L164)）**没有未来日保护**：未来的日子里，只要那天有严格任务在时间窗内、且当天开始时未完成，就会被算进 `total`；而未来日永远没有日志，所以 `done = 0`。

后果是**本月还没到的每一天都会被渲染成"欠账"**（红色贴底条），整张月历的下半月一片红。

同一个 bug 的第二现场在 DayDetailPanel：

- [DayDetailPanel.tsx:61](src/components/DayDetailPanel.tsx#L61) 的 caption 在 `ring.done === 0` 时写 `"Nothing logged yet"`，对未来的日子是在指控用户没写日志；
- [DayDetailPanel.tsx:228](src/components/DayDetailPanel.tsx#L228) 的 `missingLog` 会在未来日的每一行任务上加 `No log` 警告徽章。

**必须一起修**，否则从日历点进一个未来日，格子说"无欠账"而面板说"你什么都没写"。

修法：

- Calendar 侧：未来日走独立状态，不画水、不加绿框。
- Panel 侧：`const isFuture = day > today`；为真时 ring 不画填充、caption 改为 `"Not yet due"`、去掉警告图标，且 `missingLog` 追加 `&& !isFuture`。
- `row.overdue` **不动**——未来的日子上显示"有任务还悬着"是有意义的提醒。

`strictLogRate` 本身不改：它度量"那一天结束时的完成率"，是纯函数；"那天到了没有"是呈现层的判断。这个分界写进注释。

## 四、演示数据调整（`seed-tutorial` 分支）

数据已经改成"相对今天的偏移量"，所以它永远横跨 `今天−30 .. 今天+`，天然同时包含过去和未来。要展示日历的水位图，需要保证**五种格子状态都真实出现**：

- **清白日**（绿框）——过去某天没有任何严格任务在窗口内。目前的严格任务窗口看起来首尾相接（`fr-u4` −30..−8、`co-stats` −28..−12、`fr-u5` −7..+21），可能只有 `−8` 一天够得上。需要**拉开一段真正的空窗**。
- **欠账日**（红条）——有严格任务但一条没写。数据里已有刻意的空档。
- **部分**——已有（1/2、3/5 之类）。
- **接近完成/满**（辉光）——已有（2/2 的日子）。
- **未来日**——已有。

具体调整在实现时先跑一遍 `strictLogRate` 把当前每天的 `done/total` 打出来，看清实际缺哪几档再动手，不凭印象改。目标是**让日历上能同时出现"灌满的一周""干瘪的一周"和"清白的几天"**，三者的对比才是这个视图要表达的东西。

`9c9483b` 那个陈旧提交已在第五节处理掉，本节的所有改动只落在 `seed-tutorial`。

## 五、实现要点与分支安排

**`src/lib/dayTasks.ts`** 加两个纯函数（放这里而不是塞进组件，与该模块既有的日粒度查询保持一处）：

```ts
export interface DayMilestones { starts: Task[]; due: Task[] }
export function milestonesOnDay(tasks: Task[], day: string): DayMilestones

export type DayCellState =
  | { kind: 'future' }
  | { kind: 'clear' }                                        // 已过去/今天，无义务
  | { kind: 'owed'; total: number }
  | { kind: 'partial'; pct: number; done: number; total: number }
  | { kind: 'full'; total: number }
export function dayCellState(day: string, today: string, rate: StrictLogRate): DayCellState
```

把状态判定做成纯函数，视图只负责 switch——这样边界情况（未来日、`total === 0`、恰好 90%）能在 Node 里直接跑。

**`src/pages/CalendarPage.tsx`**：`byDay` 替换为按月的 `milestones` memo（仿现有 `rings` 的写法，[CalendarPage.tsx:44-48](src/pages/CalendarPage.tsx#L44-L48)，一次扫完 42 天）；格子加 `relative overflow-hidden`、内容包 `relative z-10`、水位块作绝对定位兄弟节点；新增由状态推导的 `water` 与 `frame` 两个 style 对象。

**`src/components/DayDetailPanel.tsx`**：按第三节改 ring 与徽章。

**分支执行顺序**：

1. 在 **main** 上做第一~三节的代码改动，提交
2. `git rebase --onto main 9c9483b seed-tutorial` —— 把演示数据变基到新 main，同时丢掉陈旧的 `9c9483b`（它会让 `merge` 误带回修好的 CHANGELOG 错误）
3. `git checkout seed-tutorial`，做第四节的 seed 调整，提交
4. 看效果就在 seed-tutorial 上跑 `npm run dev`

**seed 改动永远不进 main**；main 的 `seed.ts` 保持空实现。

## 验证

1. `npm run build`（在 main 上）—— `tsc --noEmit` 零错误。
2. 把 `dayTasks.ts` 连同 `dates.ts` / `tree.ts` / `types.ts` 取出来单独编译成 JS，在 Node 里跑判定表（本会话已用过两次这个手法）：
   - 过去且无义务 → `clear`；过去有义务没写 → `owed`；3/5 → `partial`；5/5 → `full`
   - **今天** → 按实际填写情况落在这四档之一，不能是 `future`
   - **明天及以后** → 一律 `future`，**即使那天排了严格任务**
   - 恰好 90% → `partial` 且带辉光；89% → 不带
   - `milestonesOnDay`：跨多天的任务**只在开始日和截止日各出现一次**，中间的日子不出现；父任务不出现；同时开始并截止的任务只进 `due`
3. 跑一遍 seed 的每日 `strictLogRate`，确认五种状态在数据里**都真实存在**（第四节的清单）。
4. `npm run dev`（在 seed-tutorial 上）打开 Calendar：
   - 本月下半月**不能是一片红**（本次修复的核心回归项）
   - 认真写了日志的一周读起来像"灌满的水池"，摸鱼的一周干瘪可辨，清白的几天是绿框
   - 点开一个未来日，面板显示 `Not yet due`，行上没有 `No log` 徽章
   - 点开一个过去的、没写全的日子，水位、红条、数字三者一致
5. 检查对比度：水位（0.35 透明度）与绿框在深色格底上能看清，且选中态的 accent 环仍是最强的视觉信号。
