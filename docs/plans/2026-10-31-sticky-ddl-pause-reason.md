# 便签视觉重做、任务 DDL、暂停理由

> 2026-10-31 获批，随 v0.19.0 实现。正文按最终实现写；与获批稿不同的地方就地标 `〔改动 N〕`，文末汇总。获批稿写的是「便签交互已经做完、这一轮只改视觉」，实际这一轮把便签的几何与交互也改了一轮 —— 那些改动同样标在下面。

## Context

三件事，来自用户对便签功能的反馈和两个新需求：

1. 便签的界面被判为「太屎」、风格「太老」，要求先做真正的软木板，改到第三版之后又要求放弃软木质感、改用应用自己的配色；最终是一块 16:9、从右侧滑出、靠右上角的板子。
2. 任务要有一个 DDL：只到天；过了 DDL 未完成算逾期；任务表单、详情、甘特、日历、提醒都要能看到。
3. 暂停任务要像延期一样写理由，并留在任务历史里。

## 1. 便签

### 最终做成的样子

- **入口**：工具栏右上方一个实心强调色的「便签」标签（只有图标与「便签」两个字）。点击打开一块 16:9 的板，从右边缘滑出、停在右上角；再点板外空白处或标题栏的 `»` 收起。板头也只写「便签」，不显示数量。〔改动 2、3〕
- **外观**：用应用自己的面板色、边框、强调色，不做软木照片、木框或纸纤维；卡片是普通面板卡片，贴边标签是实心强调色。〔改动 1〕
- **卡片**：按住卡片拖动；标题行是拖动区域，写着名字（默认「标签 N」），右键标题行改名；悬停出删除；八个方向都能拖边框改大小（下限 200×120）。〔改动 4、10〕
- **板内摆设**：新卡片落在板中央，之后摆哪儿是哪儿。板内**不做**自动排序、错位或吸附，卡片画的时候也不再被夹进板的矩形。〔改动 8〕
- **格式栏**：粗体（按下态跟随光标，照 Word 的做法）、A− / A / A+ 字号、文字颜色；粘贴只收纯文本；存 HTML、按白名单清洗。〔改动 10〕
- **贴边标签**：把卡片拖到页面上缘、左缘（侧栏右侧）或右缘，判据是**卡片自己的矩形**碰到那条 28px 的边（不是鼠标位置）；悬停高亮那条边。松手吸附成实心强调色标签，显示便签名；贴在左右时竖排，数字用 `text-orientation: upright` 保持正立。〔改动 9〕
  - 点标签展开回卡片；按住标签拖动可以在同一边移动、拖到另一边换边；拖离边缘时卡片**跟着指针继续走**，松手才落下。〔改动 5、6、7〕
  - 板收起时贴边标签留在页面上，板里的卡片随板滑走。
- **数据**：独立集合 `stickyNotes`，随看板保存、导出、导入；读档逐行清洗（坐标、尺寸、边、名字 80 字、正文 5 万字），缺名字补成「标签 N」。

### 实现位置

- `src/components/StickyNotes.tsx`：body portal 的一层，视口坐标；板尺寸由 `min(可用宽, 可用高 × 16/9, 680)` 算出，不测量 DOM。
- `src/components/StickyNameDialog.tsx`：改名弹窗（右键进入）。
- `src/lib/sticky.ts`：全部几何与清洗函数（夹取、堆叠号、默认名、按矩形判吸附边、HTML 白名单）。
- `src/store/storage.ts` 的 `readStickyNotes`、`src/store/useStore.ts` 的 `addStickyNote` / `updateStickyNote` / `removeStickyNote`。

### 与获批稿的差别

获批稿的视觉方案是「生成的软木 SVG 纹理 + 木框 + 三色纸片 + 金属图钉 + 卷角」，这一套**没有实现**：用户在见到第一版软木质感之后要求整个放弃（「软木板还是有点突兀……放弃软木板质感和原有配色」）。获批稿假设交互与几何已经完成、这一轮只改 CSS 与标记，实际这一轮还改了几处交互：板内不再夹取、不再自动排列，贴边判定从鼠标改成矩形，贴边标签拖出后继续跟手，另外补上了改名、缩放与格式栏。〔改动 1–10〕

## 2. 任务 DDL

### 数据

- `Task.deadline?: string | null`（yyyy-MM-dd）。与 `endDate` 无关；待办没有；阶段任务、长期目标、父任务都可以有。
- 读档归一：`deadline` 非待办保留、待办清空；`validateData` 把 `deadline` 加进日期字符串检查。导入导出随 `tasks` 走，不需要新集合。
- `NewTaskInput`、`StartTodoInput`、`addTask`、`startTodoTasks`、`TaskDialog`、`StartTodoDialog` 都带上这个字段。

### 逾期规则

`deriveTaskStatus`（`src/lib/tree.ts`）的优先级：

1. 进度 ≥ 100% → `completed`
2. 今天 > ddl → `delayed`
3. 暂停中 → `paused`
4. 今天 < 开始日 → `not-started`
5. 今天 > 结束日（非长期）→ `delayed`
6. 其余 → `in-progress`

- 完成压过一切；ddl 排在暂停之前 —— 日期不会因为任务停着就不算错过。
- ddl 早于开始日照常逾期；长期目标没有结束日期，只能被 ddl 判成逾期。
- 父任务自己的 ddl 过期且没有全部完成时，整条也 `delayed`（`effectiveStates` / `dayStates` 的父分支）。
- 当天清单的逾期徽章改为「状态是 `delayed` 就显示」，窗口内但过了 ddl 的任务也有。

### 显示

- **表单**：任务表单与开始待办各一个「ddl（可选）」日期框，下面一行说明结束日期与 ddl 的区别；三语都用 `ddl`。长期目标与父任务都显示。
- **详情面板**：起止日期下面一行只读 ddl，已过且未完成时用逾期色。
- **甘特图**：`timelineRange` 把 ddl 算进右端；`TaskBar` 在 `ddl + 1` 天处画细线加小旗，所有条形状与长期目标都画。
- **日历**：`milestonesOnDay` 的截止日改成 `deadline ?? endDate`；父任务自己的 ddl 也进日历（以前父任务整个跳过）。
- **提醒/日报/Manage**：临期与逾期都用 `dueDateOf = deadline ?? endDate`；逾期那一条写实际过去的日期。

### 检查

`scripts/check-deadline.mjs`：ddl 压过窗口逾期、完成与暂停的先后、长期目标、父任务汇总、`milestonesOnDay` 的截止日、`timelineRange` 右端。`check-data-integrity`：ddl 读档保留、非法值丢弃、旧存档缺字段读成 null。

## 3. 暂停理由

### 数据

- `Task.pauseReason?: string | null`：还没结束的这次暂停的理由。
- `Task.pauses[]` 从 `{ pauseDate, resumeDate }` 扩成 `{ pauseDate, resumeDate, reason? }`。
- 读档：`pauseReason` 只在任务确实暂停、且是字符串时保留；`pauses[].reason` 非字符串丢掉；`validateData` 允许可选 reason。
- `pauseTask(id, reason)`：trim 后为空直接拒绝。
- `resumeTask`：闭合记录里写入当前 `pauseReason`，然后清空。

### 交互

- 新增 `PauseReasonDialog`（照 `PostponeDialog`）：只有一个理由 textarea，空理由时确认按钮禁用。
- 三个入口替换原来的确认框：详情面板的暂停按钮、甘特右键「暂停」、选择栏的批量暂停。批量暂停一次弹窗、一条理由写给所有选中任务。
- 详情面板：暂停中的提示里显示理由；历史暂停列表每一行在日期下面显示理由。
- 恢复仍然只是确认框，不问理由。
- 延期与暂停理由输入框里原来那句「为什么…？」的占位删掉。〔改动 11〕

### 检查

`check-data-integrity`：空理由被拒绝、暂停→恢复后闭合记录带理由且 `pauseReason` 清空、读档保留合法理由并丢掉非字符串、批量暂停把同一理由写到每个任务。

## 实施顺序

1. 便签：`src/index.css` 与 `StickyNotes.tsx` 的标记；随后按反馈改几何（不再夹取、按矩形吸附、拖出跟手）。
2. DDL：类型 → storage → 状态派生 → 日清单徽章 → 表单/详情 → 甘特范围与旗标 → 日历 → 提醒/Manage → 检查。
3. 暂停理由：类型/归一 → store → `PauseReasonDialog` → 三个入口 → 详情 → i18n → 检查。
4. `npx tsc --noEmit`、`npm test`、`npm run build`。

## 验证

- 自动：`tsc --noEmit`、`npm run build`、23 个 check 全过（新增 `check-sticky.mjs`、`check-deadline.mjs`）。
- 手动：无头浏览器截图确认过便签板、卡片、贴边标签、负载仪表的三种读数、日程表的拖选预览与项目右键菜单；**没有在真实 Tauri 窗口里点过**，拖动与吸附手感没有被验证。
- 风险：便签的富文本依赖已废弃的 `execCommand`；便签坐标按视口像素存，窗口尺寸变化时靠夹取兜底；日程表仍然不能移动已有的块。

## 获批之后的修订汇总

1. **不做软木质感与木框**：用户连否两版（「这个ui太屎了」「风格太老了」→「软木板还是有点突兀……放弃软木板质感和原有配色」），最终是应用配色的面板。
2. **板头与标签不显示数量**：先是标签去掉计数，最后「便签窗口不要有数字 就叫便签」，板头也只剩「便签」。
3. **标签上移、改用强调色实心、打开板时隐藏**：「按钮颜色容易和gantt混」「出来之后便签按钮不要和便签窗口有干涉」。
4. **名称与改名入口**：默认「标签 N」；曾做成长输入框，被否（「名称编辑框太长了」），改成右键才进改名弹窗、名字行本身当拖动区域。
5. **贴边标签的拖出**：第一版是拖出边缘即展开、卡片定在原地；用户要求「拖出来之后我还得接着拖」，改成窗口级 pointer 监听，卡片一路跟手到松手。
6. **吸附判据从鼠标改成矩形**：「吸附的规矩不是鼠标碰到吸附区域 而是标签碰到」。
7. **贴边位置可在缩略状态调整、也能换边**：同一条边上拖动即移动，拖到另一条边即换边。
8. **板内不自动排列**：「便签窗口里的便签也是爱放哪哪 不要给我自动排序吸附」——删掉板内夹取与新卡片的阶梯摆法。
9. **竖排数字正立**：侧边标签用 `text-orientation: upright`。
10. **补上交互而不是只改视觉**：可缩放、格式栏（粗体按下态、A−/A/A+、取色）、改名，都是这一轮在实际实现中补齐的；获批稿写的是「交互与数据不动」。
11. **理由输入框去掉「为什么…」占位**：获批稿没有删除这句，用户在实现之后追加。
