# 启动时的今日规划弹窗 + 右侧提醒标签

> 2026-10-28 获批，随 v0.18.0 实现。正文按最终实现写；与获批稿不同的地方就地标 `〔改动 N〕`，文末汇总。本份与《今天页：日程表 + 每日任务规划》共用同一个计划文件（`quirky-honking-kitten.md`），写完这份时覆盖了上一份；上一份已按对话记录还原归档。

## Context

每日规划已经存在，但藏在今天页任务区的「规划」按钮后面，不点就永远不会被问到。现在把它变成一天开始时的固定动作：每次启动应用，如果今天还没有规划，弹出一个窗口问今天有多少空闲时间、打算做哪些任务；右下角「稍后再填」和「开启今日」。选稍后再填就关掉，并在窗口右上角留一个带叹号的标签；点标签重新打开。选开启今日保存规划并跳到今天页。

## 行为规则

- **启动时判断一次**：今天 `taskIds` 缺省（从未规划）且 `Prefs.planSkippedOn !== 今天` 才弹。启动之后不再自动弹（包括跨过午夜，此时只出现标签）。
- **稍后再填**：记 `planSkippedOn = 今天`，关闭；标签出现。弹窗的 X / 点遮罩等同于稍后再填。
- **标签**：条件 = 今天未规划且弹窗关着；点击重开。今天规划好之后自动消失。`z-30`：盖住页面、被右侧任务面板（z-40）和弹窗（z-60）挡住。〔改动 1、2、3〕
- **开启今日**：保存所选任务与小时（一项不勾 = 休息日），跳到今天页。
- **容量**：弹窗里可直接改，改动立即写入当天（`setDayCapacity`）；即使随后点稍后再填也保留。
- **任务计时**：每个勾上的任务填当天小时；勾「默认」把当前值记成该任务的默认工时（`Prefs.taskDefaultHours`），下次勾它自动带出。
- **统一的负载**：沿用《今天页》那份的算法（块时长与填写小时取大，自由事件与未计划任务块照常计入），弹窗与日程表列头同一个函数。
- **不新增任何计划语义**：判断仍走 `plannedIds` / `planOn`，不自动写日志、不产生「未排期」条目。

## 最终实现的形状

### `PlanDialog` 的 prompt 模式

- 标题「今天的安排」；顶部一行「今天有多少空闲时间？」，`LoadMeter` 的容量可编辑。
- 一页，不分成两步：上面是空闲小时，下面是任务列表，负载条两者之间，勾任务/填小时实时更新。
- 每个勾上的任务右侧：`[默认] [ 2 ]h`。小时框留空 = 0；已有当天小时用它，否则用该任务的默认工时。「默认」勾上 = 把当前值写进 `Prefs.taskDefaultHours`；改数字后勾选自动取消，再点一次才更新默认。
- 底部只有「稍后再填」（ghost）和「开启今日」（accent）；隐藏恢复自动 / 休息日 / 取消。X 与遮罩走同一个 `onClose`。
- 非 prompt 模式（今天页的「规划 / 调整」）用同一个对话框，同样能填小时和设默认；底部仍是原来的按钮。
- 保存时 `setDayPlan(day, ids, hours)`；prompt 模式随后 `openToday()`。

### `PlanPrompt.tsx`

- 初始 state 用惰性初始化读一次 store：`promptDue(planOn(dayPlans, today), planSkippedOn, today)`。
- 标签（收缩/展开见修订 1）。
- `onClose`：如果今天这时仍未规划，`skipTodayPlan()`；再关闭。这样「开启今日」不会留下一条无意义的推迟记录。〔改动 5〕
- 挂在 `App` 的 `<main>` 里，页面之后、`UpdateOverlays` 之前。

### 数据

- `Prefs.planSkippedOn: string | null`（日期不是布尔，跨过午夜自然失效；不进看板导出/导入）。
- `Prefs.taskDefaultHours: Record<string, number>`（任务默认工时；不进看板）。
- `DayPlan.hours?: Record<string, number>`（当天任务小时，key ∈ `taskIds`；由 `setDayPlan` 的第三个参数写入，随任务集合裁剪）。
- `setDayPlan(date, ids | null, hours?)`：`null` 同时清 `taskIds` 与 `hours`；传小时时裁到所选 id、丢掉 ≤0 / NaN；相等判断连小时一起比。
- 两个新 action `skipTodayPlan()`、`setTaskDefaultHours(id, hours | null)`，都 `persistPrefs()`。

### 检查

`check-schedule.mjs` 增加 `promptDue` 的六种情况（已规划 / 休息日 / 只有容量行 / 今天推迟过 / 昨天推迟过 / 未规划），以及 `dayLoad` 的计划小时用例（无块按小时、块与小时取大、自由事件、未计划任务块、无计划回退）。〔改动 6〕

## 获批之后的修订

1. **标签从右上角小圆点变成右边框伸出的标签，而且经历了三轮返工。** 获批稿是 `fixed top-0.5 right-0.5` 的 20px 圆角块，只有叹号。用户：「标志太小了 我要的是右侧边 上方 支出来一个比较显眼的标签」→ 改成贴右边框、32px 高、带文字「今日未规划」的标签；「再大一点点点点 然后文本从今日未规划改成今日待规划」→ 36px 高、13px 字、圆角更大；「做成常态收缩 收缩状态下只有一个叹号标志 鼠标移到上面之后展开」→ 常态 35×36 只留叹号，悬停用 `max-w` 过渡向左展开文字。
2. **标签位置从 0.5px 内缩挪到 `top-14`。** 20px 角标时代，甘特工具栏和今天页标题各加了 `pr-9` 给它让位；改成 36px 标签后，为避免压住各页右上角按钮，位置落到距顶 56px（正好在页面标题带下方），两处 `pr-9` 撤回。它仍会盖住今天页日程表卡片右上角的日期小字（规划完即消失）。
3. **文案改了两次**：右侧标签「今日未规划」→「今日待规划」；`plan.promptTag`（悬停提示）保持「今天还没有安排，点击规划」。
4. **行结构从 `<label>` 改成 `<div>` + `<label>`。** 获批稿没提，但小时框和「默认」勾选必须移出包裹整行的 label，否则点输入框会触发任务勾选。
5. **关闭时检查是否已规划。** 获批稿写「onClose 里先 skipTodayPlan 再关」；实现时发现「开启今日」也走 onClose，于是改成只有仍未规划才记 skip，避免规划完还写一条推迟。
6. **`promptDue` 落成纯函数。** 获批稿只在验证清单里提了「今天推迟过 / 未规划」两种情况；最终抽成 `lib/schedule.ts` 的函数，让 check 能直接断言六种情况。
