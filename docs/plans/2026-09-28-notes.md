# 记事本：跟任务日志共用日志页

> **这一份已经与最终实现对齐：正文说的是「做成了什么」，不是「当时打算做什么」。**
> 凡与获批稿不同的地方，就地用 **〔改动 N〕** 标出，编号对应文末的《获批之后的修订》。改动集中在**数据形状、写入口、读写形态**三处 —— 终稿与获批稿的差别比原方案本身还大，所以只把获批稿原样留档、另附一节说明是不够的：那样正文自己就会和自己打架。

## 背景

用户现在拿一个叫 `supplement for logs` **任务**顶替这件事：想写点随想、给日志补一句说明，就往那个任务里写。问题是它一旦是任务，就自动带了排期、优先级、进度、日志义务这一整套它根本不需要的东西，还会进甘特图的树、进进度汇总、进"今天要做什么"。

**要的是：一个只写、不勾、不进任何统计的地方。**

三条边界，每条都决定了它不能是什么：

- **不是任务**：用户已经用任务顶替过一轮，痛点就在这里。
- **不是临时事务（`Chore`）**：临时事务有 `done`、会滚到第二天、会进热力图。笔记没有"做完"这个状态。
- **不新增页面**：一个侧栏入口，进去之后右上角切「日志 / 记事本」。同一天可能两样都有，分到两个页面反而把它们拆开了。

所以：**一份独立集合 `Note`，跟任务日志共用日志页，靠一个切换器分开。**

## 数据

```ts
export interface Note {
  date: string      // yyyy-MM-dd —— 既是「哪天的」，也是这条的身份
  body: string      // 整段自由文字，换行就是换行
  updatedAt: string
}
```

**〔改动 1〕一天一条，`date` 就是主键，没有 `id`。** 获批稿是 `{ id, date, body, createdAt, updatedAt }`、一天可以多条，卡片上按 `createdAt` 升序逐条渲染、超出的走「还有 N 条」。用户明确否掉了那个模型：

> 不对一天内多次编辑进行区分 一天的记事本就完全是一个大文本框

于是「一天只能有一条」变成**数据形状本身**保证的，而不是每条写入路径各自记得查重。旧的「一天多条」形状在 `normalize` 里折叠，同一天的正文用空行**接起来**而不是只留最后一条 —— 那是用户写的字，是整块数据里唯一没法从别处重建的东西。

**没有 `title`。** 第一行就是标题。省一个字段，也省掉"标题填了正文空着"的空壳。

**没有 `done` / `taskId` / `projectId`。** 前者是临时事务，后者是任务日志。用户明确选了"只记日期，不挂任务"。

**`date` 可改**，因为它记的是"这篇是哪天的"，而人经常第二天才想起来补昨天的。默认值是**打开它的那一天**，不是 `todayISO()`。**〔改动 5〕改日期 = 移动**：从原日清空、写到新日；新日已有内容时两段接起来而不覆盖 —— 获批稿有日期字段，但没说改日期意味着什么。

## 界面

### 1. 侧栏那一行改成「日志 / 记事本」

`nav.logs` 的值改成 `'Logs / Notes'` / `'日志 / 记事本'` / `'Journaux / Notes'`（[i18n.ts:71](src/lib/i18n.ts#L71) / [:604](src/lib/i18n.ts#L604) / [:1063](src/lib/i18n.ts#L1063)）。只改值，键不动 —— 页面标题 `LogsPage.tsx:113` 读的就是这个键，所以标题自动跟着变成「日志 / 记事本」，不用新增键。

190px 的侧栏放得下这三个语言的值（最长是法语，约 100px）。

### 2. 页头右上角一个切换器，默认 logs

页头从 `<h1>` 变成一行两端对齐：左标题，右切换器。

**复用现成的 `Segmented`**（[ui.tsx:50-74](src/components/ui.tsx#L50-L74)）—— 它已经带 `bg-accent/15 text-accent` 的选中态和 `transition-colors`。两个选项的文案：`logs.tabLogs`（日志 / Logs / Journaux）和 `notes.title`（记事本 / Notes / Notes）。

模式是 `LogsPage` 的局部 `useState<'logs' | 'notes'>('logs')`，**不持久化** —— 从侧栏进来永远是 logs，就是"默认展示 logs"。

### 3. 两种模式各显示各的，卡片下方压着第二张

- **logs 模式**：有日志的那些天，卡片正文是现在那套任务预览（[:154-174](src/pages/LogsPage.tsx#L154-L174)）。
- **notes 模式**：有笔记的那些天，卡片正文换成那天的笔记。**〔改动 1〕一天只有一条**，所以「前两条 + 还有 N 条」那套没了；卡片高度有限，正文到第 3 行截断（`line-clamp-3`），点开才看得全。
- **两样都有的那天，卡片底下压出第二张卡的边** —— 就是用户要的那个信号：

```tsx
<div className="relative">
  {hasBoth && (
    <div
      aria-hidden
      className="absolute inset-0 rounded-2xl bg-panel2 border border-border"
      style={{ transform: 'rotate(3deg) translate(4px, 5px)' }}
    />
  )}
  <button className="relative ...">…</button>
</div>
```

**〔改动〕第一版做成了另外的样子。** 获批稿写的是"比卡片窄 12px、往下探 6px 的一条边"，实现出来看着就是个投影。用户看了实机之后：

> 那个第二张压在底下的表示没有那么明显 可以是和第一张错一个角度 然后稍微偏离一点点 你体会一下 有点散落的放着的感觉

所以改成整整一张卡转 3°、往右下错开，靠前面那张的 `shadow-md` 压出上下关系；网格行距同时从 `gap-4` 放到 `gap-y-6`，给垂下来的那个角留地方。

**两种模式下都画** —— 它说的是"这天两样都有"，跟当前在看哪种无关。第二张卡是纯装饰（`aria-hidden`），它表达的信息**卡片底部那行计数里已经有一份文字**（见下），所以读屏用户不会漏掉。

- **笔记预览不带项目圆点、不带状态色**（`colour-carries-one-meaning`：状态色只表示状态）。区别靠**形式**：左侧一道竖线 `border-l border-line pl-2`、正文用正常文字色；日志那边是"· + 缩进"的条目形状。一眼能看出这边是散文不是进度。
- **〔改动 1〕同一天的笔记不再有次序问题** —— 一天只有一条。获批稿里那条"按 `createdAt` 升序、早上写的在上面"随模型一起作废。

### 4. 卡片底部计数改成三段拼

现在 `logs.dayFooter` 是 `'{logs} · {tasks}'`（[i18n.ts:297](src/lib/i18n.ts#L297)）。有了笔记之后会出现"一天只有笔记"的卡片，那时它渲染成"0 条日志 · 0 项任务"—— 一句话说了两遍没有。改成页面内拼，空的那段直接不出现：

```tsx
// 〔改动 1〕终稿里第三个是 `note` 而不是 `dayNotes` —— 一天只有一条，
// 所以计数恒为 1，不再取长度。
const footer = [
  dayLogs.length ? t('common.logCount', { count: dayLogs.length }) : null,
  taskEntries.length ? t('common.taskCount', { count: taskEntries.length }) : null,
  note ? t('common.noteCount', { count: 1 }) : null,
].filter(Boolean).join(' · ')
```

`logs.dayFooter` 因此变成死键，**三语各删一处**。

### 5. 左侧项目筛选树在 notes 模式下收起来

笔记没有 project，那棵树在笔记模式下点了什么都不会变 —— 一个点了没反应的筛选器就是在骗人。所以切到 notes 时整个 `<aside>` 不渲染，网格占满宽度。

**〔改动 6〕而且 `withNotes` 收到的日志此时根本不过滤。** 获批稿写的是"项目 / 任务筛选下不显示笔记"，实现时发现还差一层：如果只藏树、仍然按筛选过滤日志，那么一个看不见、也管不着列表内容的筛选器，仍然会决定"这天两样都有"那道边画不画。所以 notes 模式下筛选整个不参与计算（筛选本身保留不清理，切回日志时落回原处）。

### 6. 切换的动画

这个仓库目前一个 `@keyframes` 都没有，全靠 Tailwind 的 `transition-*`（`DayBoard.tsx:548`、`TodayPage.tsx:104`）。但"内容被换掉"用 transition 表达不了，得靠重挂载时重播动画。所以给 `src/index.css` 加四行，网格上挂 `key={mode}`：

```css
@keyframes swap-in { from { opacity: 0; transform: translateY(6px) } }
.swap-in { animation: swap-in 160ms ease-out }
@media (prefers-reduced-motion: reduce) { .swap-in { animation: none } }
```

`key` 一变 React 重挂载网格，动画重播。160ms、6px —— 是"换了一页"而不是"弹了一下"。

## 写在哪里

**写入口只有一个：点卡片打开的那个日详情弹窗。** 两种模式下点卡片打开的都是它，里面两节都在：任务日志那节原样不动，**后面加一节「记事本」**。

- 列出当天的笔记，每条一张卡，正文 `whitespace-pre-wrap`，右侧一对 Pencil / Trash —— 跟同文件里的日志卡一模一样。
- 节标题右边一个「＋ 写点什么」，打开 `NoteDialog`（日期预填这一天）。

**写在弹窗里而不是卡片上**，跟日志一致（日志也是点 Pencil 开 `LogDialog`），而且免掉“失焦即存”在点了删除之后再触发一次保存这类脏事。

**〔改动 3、4〕这一节整体被推翻了两次。** 终稿是：

- **三个写入口，不是一个。** 获批稿「明确不做」里写着 `DayBoard` 不动，那是错的 —— 用户要「在 today 和日期详情页里都设置编写入口」，而这两处渲染的都是 `DayBoard`。
- **读写分开，不常驻编辑。** 第一版实现成了一个一直张着的 textarea、失焦即存、还没有日期字段，被否：

  > 为什么在 logs/notes 里写记事本无法更改日期 然后所有位置也都没有底下的 save 了 我想的是 记事本不是一直处于编辑状态 起码有个点进去再编辑然后 save 这种好一点

  终稿的读态是**一张圆角卡片**（与日志卡片同形状），标题那一行的右端是**查看**与**编辑**两个按钮、悬停显示。**查看是获批稿里没有的**：一个 620px 的只读弹窗，因为 320px 的面板够你看出「写了东西」，不够读一整段。
- **日志页日弹窗那一节是可选的**（`notes?: { note: Note | null }`）—— 日面板自己就有记事本，同一个屏上不该有两个。用可选对象当开关而不是 `Note | null`，是因为后者分不出「不画」和「画一个空的」。
- **追加与改写拆成两个入口**（见下面的页头按钮），所以 `NoteDialog` 复活成「开一个空框、保存即追加」，和 `NoteBox` 的编辑器并行存在。

### 页头的「写点什么」：追加，不是改写

**notes 模式下，页头切换器旁边有一个 `＋ 写点什么` 按钮**，日期默认今天。获批稿给它的理由是「一个还没有任何笔记的日子没有卡片」，那个理由仍然成立；但**它的语义是后来才定清楚的**：

> logs/notes 里写点什么 属于为选定的日期增加文本而不是直接更改该日期的文本 也就是说从该入口里点进去 文本框应该是空的

所以它开一个**空**框、保存即 `appendNote`；而「编辑」开的是装着整天正文的框、保存即 `setNote` 改写。**〔改动 4〕store 里因此是两个动作而不是一个带参数的** —— 「这一天现在就是这个」和「这段加在它后面」不是能从一个动作里猜出来的差别。

logs 模式下不显示这个按钮（那个位置写出来的会是笔记不是日志，放那儿是误导）。

## 获批之后的修订

以下是获批**之后**才定下来的部分。原方案里的界面模型基本被推翻了 —— 终稿与获批稿的差别比原方案本身还大。

**正文里对应的地方都标了 `〔改动 N〕`，编号就是下面的编号**；这一节是汇总，两处说的是同一批改动。

### 1. 数据形状换了：一天一条，`date` 当主键

批准时是 `Note { id, date, body, createdAt, updatedAt }`，一天可以有多条：卡片上按 `createdAt` 升序逐条渲染，超出的走「还有 N 条」。用户随后明确：

> 不对一天内多次编辑进行区分 一天的记事本就完全是一个大文本框

于是改成 `Note { date, body, updatedAt }`，**没有 `id`**。「一天只能有一条」因此是数据形状本身保证的，不是每条写入路径各自记得查重。连带：`withNotes` 返回的从 `notes: Note[]` 变成 `note: Note | null`；`lib/notes.ts` 多一个 `noteOn(notes, day)`；卡片上「还有 N 条」那行、逐条的编辑/删除按钮、`common.noteCount` 的复数全部作废。

旧的「一天多条」形状在 `normalize` 里按日期折叠，**用空行接起来**而不是只留最后一条 —— 那是用户写的字，是整块数据里唯一没法从别处重建的东西。

### 2. 写入口从一处变成三处，`DayBoard` 改了

原方案「明确不做」的第一条写着 `DayBoard` 不动。用户要求「在 today 和日期详情页里都设置编写入口」，而这两处渲染的都是 `DayBoard`，所以它加了 `NoteSection`；`Section` 因此多了一个 `action` 插槽（标题行右端，悬停显示）。`DayLogsModal` 的笔记区随之变成**可选** —— 日面板那边自己就有记事本，同一个屏上不该有两个。

### 3. 读写形态推翻两次

- **获批稿**：读态是正文，点开 `NoteDialog`（日期 + textarea + 保存）。
- **第一版实现**：一个**常驻编辑**的 textarea，**失焦即存**，没有日期字段。被否：

  > 为什么在 logs/notes 里写记事本无法更改日期 然后所有位置也都没有底下的 save 了 我想的是 记事本不是一直处于编辑状态 起码有个点进去再编辑然后 save 这种好一点

- **第二版**：读/编辑分开，`NoteBox` 自己带日期与取消/保存。
- **终稿**：编辑按钮挪到「记事本」那一行的行尾，**查看**与**编辑**并排，都是圆角矩形按钮、悬停显示；读态从裸文字改成**圆角卡片**（与日志卡片同形状）—— 用户反馈裸文字「看着太塑料了」，并且要求在 Today / 日面板里「得能查看」。

**查看是计划里没有的。** 一个 620px 的只读弹窗：320px 的面板够你看出「写了东西」，不够读一整段。

### 4. 追加与改写拆成两个入口

获批稿只有一个 `NoteDialog`。用户要求：

> logs/notes 里写点什么 属于为选定的日期增加文本而不是直接更改该日期的文本 也就是说从该入口里点进去 文本框应该是空的

于是 store 里是 `setNote` / `appendNote` 两个动作，**没有合成一个带参数的** —— 「这一天现在就是这个」和「这段加在它后面」不是能从一个动作里猜出来的差别。`NoteDialog` 因此复活成「开一个空框、保存即追加」，与 `NoteBox` 的编辑器并行存在。

### 5. 改日期 = 移动

获批稿的 `NoteDialog` 有日期字段，但没说改日期意味着什么。终稿定成：**从原日清空、写到新日**；新日已有内容时两段**接起来**而不是覆盖 —— 移动到一个已有内容的日子很少见，而覆盖是唯一回不去的结果。

### 6. 项目筛选：不是「不显示笔记」，是整棵树收起来

获批稿写的是「项目 / 任务筛选下不显示笔记」。实际是 notes 模式下整个 `<aside>` 不渲染，且 `withNotes` 收到的日志**根本不过滤** —— 否则一个看不见、也管不着列表内容的筛选器，仍然会决定「这天两样都有」那道边画不画。

### 7. 计划外的改动：默认窗口尺寸

> 除此之外软件每次打开都默认全屏

查下来没有任何地方设置全屏（`fullscreen: false`，没有 window-state 插件，Rust 里没有 `maximize`）。真实原因是 `1280×800` 在这台机器（逻辑工作区 1707×1019）上占 75% 宽、78% 高。用户要的是**改大**、并且固定默认，于是改成 `1440×900`。顺带说明：这两个约束在这块屏上不能同时满足 —— 1440×900 是 84% × 88%，比原来**更像**全屏。

### 8. i18n 的键换过一轮

获批稿列的是 `notes.title` / `notes.empty` / `notes.add` / `notes.placeholder` / `common.noteCount`，另删 `logs.dayFooter`。实现中途加过 `notes.more`、`notes.deleteAsk`（一天多条的遗留）和 `notes.appendHint`（一条「会接在后面」的提示），随模型简化和用户要求（「不要你那个什么 今天已经写过了所以怎么怎么的解释 删掉」）**全部删掉**；后来加了 `common.view`，以及在 `notes.empty` 之外又加了 `notes.none` —— 空的记事本显示「暂无」，不是「写点什么」。

### 9. 验证方式与计划不同

计划里那条手动清单（第 3 项）**大部分没跑成**：这个仓库没有任何浏览器自动化工具，全局也没装，我没有替用户装 Playwright。实际做完的是 `npm run build`（含 `tsc --noEmit`）与 `scripts/check-notes.mjs`，并对后者做了变异测试 —— 把「只有笔记的天也要出现」和「同一天重写要替换不要追加」分别改坏，确认断言确实会挂，改回来再通过。**界面本身从头到尾没有被亲眼看过。**
